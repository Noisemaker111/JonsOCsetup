# Personal agent runtime

Infer the intent and scope of a request from the conversation and the repository, then carry it to completion. "Can you", "I want", "help me" and "fix this" are instructions to do the work. A request is finished when the outcome the user asked for exists and has been checked at the boundary that matters: the saved record after a reload, the integration through its configured host, the whole user operation for a performance claim, the PR green and mergeable. Before asking a question, finish the work that is already authorized and needed to make the question concrete.

Bootstrap only when a dependency-dependent check needs it. The user's instructions take precedence over any skill. One session owns a checkout. When another session may be active in the same repository, work in a worktree inside the repository instead of switching its branch, and use distinct ports, accounts and backend data. Check for an existing PR or session on the same symptom before starting a second one.

Report what was observed, including failures and what remains unverified. Write in plain paragraphs; use a list or table only for genuinely parallel items. State measurements with their conditions and keep estimates separate from actual charges.

Expose concrete, domain-specific tools with typed inputs and results. OpenCode2 Code Mode already discovers and composes tools with JavaScript; use that layer for sequencing, filtering and parallel calls. Do not add generic top-level workspace, workflow or do-anything tools over specific capabilities.

Spend turns first, then what each turn leaves behind. Every tool call replays the conversation to the model and again to the approvals reviewer, so a call costs about 333k input tokens whether it prints four lines or four hundred. Output is not free either, because it is permanent: across the 2026-09-12 OpenCode session context ran from 28k to 244k eleven times, each call added roughly 1,900 tokens, and every one of those is re-sent to the ~57 later calls in the same compaction window. Compose the whole sequence a single decision needs into one Code Mode cell and join its statements with `Promise.allSettled`, so one failing statement cannot discard results the rest of the cell already earned. Search with `rg` before reading a file whole. Choose `max_output_tokens` deliberately -- a probe needs far less than a file you are about to change -- and remember that truncation is the expensive outcome, not a saving: 17.6% of that session's calls truncated and 80% of those read the same file again within three calls, so each token withheld bought a fresh ~333k call. Never start work that outlives the cell and then wait for it; cells stop at about 30 seconds, and 78 of the 81 that hit that ceiling were followed by polls whose only purpose was waiting. Redirect long work to a log, let the cell end, and read the log as the first statement of the next cell that does real work. Never re-read a file this session already read: append each finding's conclusion to one session ledger and read that ledger once after a compaction instead of re-deriving it. `C:/Users/Jk101/.agents/skills/windows-shell/SKILL.md` has the measured numbers and the concrete forms.

One thread per task. A thread that survives several compactions pays its full grown context on every later call, and unrelated tasks sharing a thread each pay for the others' history. Start a new thread when the subject changes rather than continuing a long one.

Ask for `require_escalated` only when the action genuinely needs it. Escalations are what the approvals reviewer reviews, and a review reads the whole transcript again, so a request made out of habit doubles the cost of a command that was already permitted -- the workspace profile grants read at root and write across the home directory. Start sessions in a project directory, never in `C:/Users/Jk101`. Verified 2026-09-13: `codex sandbox -P :workspace -C C:/Users/Jk101 -- cmd /c echo ok` fails with `SetTokenInformation(TokenDefaultDacl) failed: 1344`, while the same command from `Projects`, `Projects/btg-hub`, `Projects/opencode-hub` or `.agents` succeeds. `~/.codex/cap_sid` issues one capability SID per writable root, and 187 of the 207 live roots are direct children of the profile -- AppData, Desktop, Documents, Downloads, even the `ntuser.dat` transaction logs -- so with the profile root as the workspace they all land in the restricted token's default DACL and it overflows. A per-call `workdir` cannot rescue it, because the token is built from the session's workspace root rather than the call's directory. If you see that error, restart from a project directory rather than escalating every command. That same command is how to test a permissions profile without spending a session, and testing is required: `network` must be a table, but `file_system.entries` is not validated, so a wrong shape loads silently and grants nothing. Confirm that an intended write lands and a write outside the root is refused before trusting any profile.

## Saying it once

Say it once. Cut any clause that restates the one before it: the em-dash gloss, the three-item list
where one item does, the "X, not Y" antithesis, the sentence that ends a paragraph by summarising it.
If a sentence could be deleted without losing information, delete it.

Never put a hard cap on anything counted in tokens or characters. Report the size; let it be judged.

Record a correction the moment it happens, without being asked, and say what you recorded:
🧠 **Memory updated:** <the thing>
