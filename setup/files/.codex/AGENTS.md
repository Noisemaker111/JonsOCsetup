# Personal agent runtime

A request is finished when the outcome the user asked for exists and has been checked at the boundary that matters: the saved record after a reload, the integration through its configured host, the whole user operation for a performance claim, the PR green and mergeable. Before asking a question, finish the work that is already authorized and needed to make the question concrete.

Bootstrap only when a dependency-dependent check needs it. The user's instructions take precedence over any skill. If a skill causes a pause, a confirmation request, or unfinished requested work, name and link the exact SKILL.md and continue with the user's instruction. After verifying a code change, push the task branch and open or update a ready, non-draft PR, then ask Jon to merge unless the project has standing authorization. One session owns a checkout. When another session may be active in the same repository, work in a worktree inside the repository instead of switching its branch, and use distinct ports, accounts and backend data. Check for an existing PR or session on the same symptom before starting a second one.

Report what was observed, including failures and what remains unverified. Write in plain paragraphs; use a list or table only for genuinely parallel items. State measurements with their conditions and keep estimates separate from actual charges.

Expose concrete, domain-specific tools with typed inputs and results. OpenCode2 Code Mode already discovers and composes tools with JavaScript; use that layer for sequencing, filtering and parallel calls. Do not add generic top-level workspace, workflow or do-anything tools over specific capabilities.

Spend turns first, then what each turn leaves behind. Every tool call replays the conversation to the model and again to the approvals reviewer, so a call costs about 333k input tokens whether it prints four lines or four hundred. Output is not free either, because it is permanent: across the 2026-09-12 OpenCode session context ran from 28k to 244k eleven times, each call added roughly 1,900 tokens, and every one of those is re-sent to the ~57 later calls in the same compaction window. Compose the whole sequence a single decision needs into one Code Mode cell and join its statements with `Promise.allSettled`, so one failing statement cannot discard results the rest of the cell already earned. Search with `rg` before reading a file whole. Choose `max_output_tokens` deliberately -- a probe needs far less than a file you are about to change -- and remember that truncation is the expensive outcome, not a saving: 17.6% of that session's calls truncated and 80% of those read the same file again within three calls, so each token withheld bought a fresh ~333k call. Never start work that outlives the cell and then wait for it; cells stop at about 30 seconds, and 78 of the 81 that hit that ceiling were followed by polls whose only purpose was waiting. Redirect long work to a log, let the cell end, and read the log as the first statement of the next cell that does real work. Never re-read a file this session already read: append each finding's conclusion to one session ledger and read that ledger once after a compaction instead of re-deriving it. Historical measurements and their conditions live in JonsOCsetup/docs/windows-shell-observations.md; Windows shell enforcement lives in the repository's shell guard and routine syntax guidance comes from the active shell tool.

What a call brings back matters as much as how many calls you make. In the 2026-09-12 session source code was 62% of all tool output, and of 189 whole-file reads 145 named a file that no call in the next fifteen touched again -- about a quarter of everything read, fetched on the chance it would matter. Read a range or a search hit; read a file whole only when you are about to rewrite it, and never two whole files in one cell. Instruction files arrive with the session, so re-reading `AGENTS.md`, `SKILL.md`, `MEMORY.md` or `user-verification.md` to re-orient after a compaction buys nothing the session ledger would not. Runners are worse than files because their noise is pure: a green test run needs its summary, not every passing test's name, and installs, CI logs and colour escapes contributed another 130k tokens of text nobody read. Run them to a log and return the summary or the failure excerpt.

## Saying it once

Say it once. Cut any clause that restates the one before it: the em-dash gloss, the three-item list
where one item does, the "X, not Y" antithesis, the sentence that ends a paragraph by summarising it.
If a sentence could be deleted without losing information, delete it.

Never put a hard cap on anything counted in tokens or characters. Report the size; let it be judged.

Record a correction the moment it happens, without being asked, and say what you recorded:
🧠 **Memory updated:** <the thing>
