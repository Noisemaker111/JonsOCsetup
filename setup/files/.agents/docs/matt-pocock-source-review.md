# Matt Pocock official docs review

Reviewed 2026-09-05 from `mattpocock/skills` commit `3cca18b368ae95cdbdebbff572ccafa662551015`. All 25 `docs/**/*.md` catalog documents were read in full. Comparisons below use the authoritative SKILL.md rather than treating catalog prose as an executable specification. This is a bounded reading report, not an invocation of the planning or implementation flows.

## Findings that affect this installation

- The intended route is setup, then a grilling conversation for a single-session decision or wayfinder for foggy work spanning sessions. A clear wayfinder map returns to to-spec, then to-tickets and implement; the router permits skipping the spec only when work proves small. The router is a map of this pack, not a general discovery tool for all installed skills. [ask-matt SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/ask-matt/SKILL.md)
- Local markdown is explicitly supported without a remote, with issues under `.scratch/<feature>/`. GitHub and GitLab have templates; Linear is an Other workflow recorded as prose. Setup writes tracker, triage mapping and domain-layout docs; it does not edit vendor skills. [setup SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/setup-matt-pocock-skills/SKILL.md)
- Preserve the whole skill directory, including supporting references and scripts. The grilling wrappers depend on `grilling`, and `grill-with-docs` also depends on `domain-modeling`. TDD references `tests.md`, `mocking.md` and `codebase-design`; setup needs seed templates. Copying only SKILL.md breaks these dependencies. [grilling docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/productivity/grilling.md), [tdd SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/tdd/SKILL.md), [setup SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/setup-matt-pocock-skills/SKILL.md)
- Keep durable adaptations in AGENTS.md or invocation text: the docs explicitly warn that changing vendor SKILL.md is overwritten by `npx skills update`. [ask-matt docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/ask-matt.md)

## Material discrepancies and qualifications

1. **Prototype retention has changed.** Current SKILL.md says capture runnable evidence on a throwaway branch outside main and link it from the implementation issue. Keep the decision in main; do not assume throwaway means deleting the evidence. This supersedes older summaries that say discard all prototype code. [prototype SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/prototype/SKILL.md)
2. **Wayfinder has an execution escape hatch.** Its SKILL.md defaults to decisions, but permits effort Notes to override into execution. The user's explicit workspace rule must remain stronger: no agent-authored Notes can authorize product work. The docs describe the escape hatch as a common failure. [wayfinder SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/wayfinder/SKILL.md), [wayfinder docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/wayfinder.md)
3. **The spec step includes a seam check.** “No interview” does not mean no human exchange at all: SKILL.md explicitly sketches testing seams and checks them with the user before publishing. It must synthesize settled product decisions without inventing new ones. [to-spec SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/to-spec/SKILL.md)
4. **Implement's literal instructions are much smaller than its docs.** The body says implement the spec/tickets, use TDD where possible at agreed seams, run feedback loops, code-review, and commit to current branch. It does not itself enforce one ticket, prohibit every clarification, close tickets, reconcile acceptance boxes, or open a PR. The one-ticket policy exists in the wider flow and in this user's own rules. [implement SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/implement/SKILL.md), [implement docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/implement.md)
5. **Review ordering has a real mismatch.** Implement requests review before commit, but code-review uses `git diff <fixed-point>...HEAD`, which excludes uncommitted work. A later invocation must select a reviewable committed diff or explicitly adapt the review scope; installation itself requires no product commit. [implement SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/implement/SKILL.md), [code-review SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/code-review/SKILL.md)
6. **TDD is red-green, despite its trigger phrase.** Frontmatter still mentions red-green-refactor, while the body explicitly moves refactoring to review. [tdd SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/tdd/SKILL.md)
7. **Docs contain stale counts and stronger summaries.** ask-matt docs refer to 22 plugin skills and 13 user-only skills; those numbers should not replace the current catalog/plugin inventory. wayfinder docs say there is no guidance for invalidated decisions, but SKILL.md explicitly says to update or delete invalidated tickets. [ask-matt docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/ask-matt.md), [wayfinder SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/wayfinder/SKILL.md)

## Harness and local-use pitfalls

- Setup selects an existing CLAUDE.md before AGENTS.md even in Codex. Put the actual pointers in the instruction file the active harness reads; the user has explicitly requested AGENTS.md. [setup SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/setup-matt-pocock-skills/SKILL.md)
- User-only skills can be omitted from a model's discovered list and then falsely declared absent. Check the installed directory/manifest, and explicitly load named dependencies. Do not infer missing installation solely from an injected skills list. [ask-matt docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/ask-matt.md), [grill-with-docs docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/grill-with-docs.md)
- Several references name Claude's `Skill` or `Agent` tools literally. Adapt their meaning to the active harness's skill loading and delegation facilities; a directory copy alone does not verify OpenCode invocation or subagent behavior. The wizard docs give `$wizard` for Codex and `/wizard` for Claude. The 25 docs do not establish exact OpenCode discovery directories or slash-command wiring; those need the current OpenCode source/docs and local inspection outside this review. [codebase-design docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/codebase-design.md), [architecture docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/improve-codebase-architecture.md), [wizard docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/wizard.md)
- Research and code-review can recursively delegate because their subagent briefs lack a stop. A bounded worker should perform its assigned reading/review directly. This review did so and spawned no further agents. [research docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/research.md), [code-review docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/code-review.md)
- `teach` mixes skill-relative references and workspace-relative output paths. Name the teaching workspace explicitly. Handoff files go to OS temp, so carry them somewhere persistent if the destination session may not share temp. Wizard and the diagnosing-bugs human loop use bash, which requires an available bash environment on Windows. [teach docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/productivity/teach.md), [handoff docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/productivity/handoff.md), [wizard docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/wizard.md), [diagnosing-bugs docs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/diagnosing-bugs.md)

## Limits

This report read source files from the pinned official clone. It did not independently reproduce the docs' community bug reports, verify their linked issue status live, test every skill workflow, inspect the parent agent's installed directories, or prove command discovery in a restarted ChatGPT/Codex or OpenCode session. Documentation anecdotes above are identified as documentation claims; directly compared SKILL.md behavior is the authoritative basis for adaptation.
