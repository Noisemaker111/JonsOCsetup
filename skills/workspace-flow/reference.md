# Prepared Quest workspaces

Normal startup remains opencode2. Giver list/get/create/update calls request one prepared spare per project; a hidden Bun subprocess performs Git and the configured bootstrap, with a two-minute bootstrap timeout. Worker calls and model run itself do not initiate preparation. Nothing runs an extra model or changes the requested route. Preparation is opportunistic, not an OS scheduler; no supporting host means no background preparation.

Assignment checks the source revision, bootstrap argv, project and physical ownership, and workspace snapshot integrity. A source change between assignment and prompt fails before prompting. Dependency and retry snapshots continue through the existing snapshot path. Cold starts remain possible. Prepared workspaces use a short physical warm ID even when the runtime run ID is long. A dispatched workspace is never handed to another run. Only the unassigned spare is limited to one per project; there is no new cap on active or retained worker workspaces. Existing historical worktrees are preserved and not counted as newly allocated work.

Cleanup replaces only unassigned stale spares that still exactly match their recorded source snapshot and have no added worker commits or files. The owned path is verified before removal. Assigned/unknown work is retained. Existing QuestWorkspaces.cleanup verifies cleanliness and commit ancestry; its caller must additionally establish that no worker is live before invoking it. There is no automatic deletion of assigned workers or blanket pruning. Integration and verified retirement are required before removing assigned work; this implementation does not invent host liveness proof or alter concurrency policy.

The compact workspace-flow skill is model-discoverable, with a read-only Node preflight helper. The helper reports only directory, revision, dirty-file count and Git operation state; it does not pretend to acquire a lock. Workers receive an ownership/bootstrap receipt in their existing prompt and should not repeat inventory or installation. The global AGENTS trigger applies in new sessions; already-open sessions need to read it or load the skill explicitly.

Verification receipts and measured limits are recorded after the isolated checks. Readiness is a checked snapshot, not a guarantee against arbitrary external mutation after execution begins. No existing terminals or legacy worktrees are terminated or removed by installation.

Source freshness includes HEAD, tracked changes and untracked file contents. This also preserves an intentionally dirty coordinator checkout (for example its local activation pointer) without copying a stale snapshot. Ignored bootstrap outputs are trusted after the configured bootstrap succeeds; external mutation of ignored dependencies is outside this fingerprint. Source is checked again immediately before a model prompt.

Native source acceptance: `bun scripts/verify-astra-recovery.ts --prepared`, exit 0, all 13 checks passed. Receipt: `.visual-e2e/astra-capability-1788716596227/report.json`. One native openai/gpt-6-astra#medium worker consumed a prepared workspace, discovered workspace-flow, wrote/read/ran shell checks, and the dependent command continued. The small local fixture measured approximately 0.6 seconds to claim a prepared workspace; model response latency is separate.

## Global workspace mode

Use `/quest-workspace` or the command palette entry **Quest workspace mode (global)**. Select Separate worktrees or Shared project checkout. The giver can also use typed `quest({action:"update",update:{workspaceMode:"shared"}})` (or worktree). The setting lives in the personal config quest-settings.json and is read for every future run; changing it does not move active workers. The default remains worktree. The portable skill preflight reports the same setting to Codex.

In shared mode run.files contains literal relative file/directory scopes. Omission reserves the whole checkout. Disjoint workers share the original directory and the same atomic coordination ledger as Codex; overlap, parent-directory overlap, traversal and alias escape are rejected. Native quest_workspace exposes the shared reservation view. Workers may refresh activity but cannot widen or release their assignment themselves. Shared mode does not repeat dependency installation: prepare dependencies once under exclusive checkout ownership. Commits, branch changes and index operations require exclusive checkout ownership too. These are cooperative rules; arbitrary external editors and shell side effects are not sandboxed.

Observed terminal outcomes collect scope-limited results then release ownership; an unknown launch keeps its reservation. Ended shared assignments cannot resume mutation tools without a new Quest dispatch. Shared root cleanup is disabled. Switching to shared mode with unintegrated isolated dependencies reports an integration blocker; switching to worktrees snapshots the existing shared result once. No mode changes model selection or existing account concurrency policy.
